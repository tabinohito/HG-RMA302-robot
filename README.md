# HG-RMA302：F310で左右の車輪速度を操作

Linux PCに接続したF310から、ST-Link仮想COM経由で2枚のB-G431B-ESC1を操作します。左スティックで左右輪の目標速度を指定し、ESCが電流を調整して速度を保ちます。前進・後退・旋回・その場旋回に対応し、WT61は使いません。

現在の設定は**車輪の目標速度8〜25 RPM、各輪のq軸電流上限2 A、始動電流0.6 A**です。2 Aはバッテリー入力電流の指定ではありません。車輪を浮かせた試験用で、接地・実負荷での走行確認はまだです。LB解放などによる停止はPWMを切る動作で、保持ブレーキではありません。

## 起動と操作

```bash
uv sync
# 入力だけを表示。ESCは接続しない
uv run hg-cart gamepad

# 左右の目標速度を表示。モーターは動かない
uv run hg-cart drive --config config.local.json

# 実際にモーターを操作
uv run hg-cart drive --config config.local.json --live
```

走行プログラムと入力モニターは同時に実行しないでください。ゲームパッドを排他取得し、シリアルも排他オープンします。終了はCtrl-C、時間を区切るには `--seconds 120` を付けます。

1. スティックを中立にし、LBを離して `READY` を確認します。起動直後はLBを一度押して離すと入力が更新されます。
2. 中立でLBを押し、そのまま保持して左スティックを動かします。
3. LBを離すと両輪のPWMを停止します。

| 操作 | 動作 |
| --- | --- |
| 左スティック上・下 | 前進・後退の目標速度 |
| 左スティック左右 | 左右の速度差で旋回。上下中立ならその場旋回 |
| LB解放 | 両輪のPWM停止 |
| B | 両輪を停止し、停止状態を保持 |
| スティック中立・LB解放でStartを押す | Bによる停止保持を解除。改めてLBで操作許可 |
| LB保持のまま車輪指令の符号を反転 | 該当する車輪を制御減速し、最新の方向へ再始動。他方の車輪は継続 |
| LB保持のままスティック中立 | 制御減速後にPWM停止。LB保持中は次の指令を受け付ける |

**LBは長押しに対応しています。** 保持中の反転はESCが `decelerate` → `settle` → `align` → `ramp` → `blend` → `closed` と処理し、ホストの固定2.5秒待機は入りません。内輪だけの反転で外輪を止めず、途中で変えた目標も最新値を使います。LBを離すかBを押すとPWMを即時停止し、保留中の再始動を取り消します。

ホールなしのセンサレス制御です。減速時は最大 `min(0.6 A, 電流上限)` の逆向きIqを使い、低速になった後は300 msの相短絡で減速してから再始動します。停止位置や完全な静止を外部センサーで測っているわけではありません。ゼロ速度を跨ぐ完全な連続FOCではなく、反転時には推定を取り直す始動時間が残ります。

LB解放・異常などでPWMを切った後、新しくLBを押して逆方向へ始動するときは、従来どおり停止待機があります。その場合だけ `DIRECTION_CHANGE_WAIT` と残り時間を表示します。

非ゼロ指令の範囲は8〜25 RPMです。**0〜8 RPMを連続指定することはできません。** 前後・旋回を合成した後、左右の速度比を保って最大輪を8〜25 RPMへ割り当てます。内輪の計算値が8 RPM未満ならゼロへ落とし、旋回時に内輪まで8 RPMへ持ち上げないようにしました。`steering_gain` で旋回の強さを調整できます。速度目標の変化率は `acceleration_rpm_s`（初期値20 RPM/s）です。

画面の `RPM_cmd` はESCに送る符号付き指令、括弧内のRPMはセンサレス推定速度です。右モーターは前進時に負符号なので、前進の最大操作で `L=+15 / R=-15` と表示されます。

## 接続と設定

```text
F310（XInput） → USB → Linux PC / Python
                       ├─ ST-Link VCP → 左ESC → 左走行モーター
                       └─ ST-Link VCP → 右ESC → 右走行モーター
```

USBとは別に走行用電源が必要です。現在のESC保護範囲は18〜22 V、相電流トリップ4 Aです。Pythonは電圧・相電流保護を上書きしません。

2026-10-13にユーザーの目視で確認した接続を `config.local.json` に保存しています。ポートを入れ替えるときはモーター定数も一緒に入れ替えてください。

| 車輪 | ST-Linkシリアル番号 | 前進符号 | R [Ω] | L [H] |
| --- | --- | ---: | ---: | ---: |
| 左 | `0670FF343433464757213550` | +1 | 1.887 | 0.000881 |
| 右 | `0665FF535157808667132326` | -1 | 1.850 | 0.000930 |

ESCはUSBの固有シリアル番号で左右を識別します。`config.local.json` は次の設定に更新済みです。

```json
{
  "left_serial": "0670FF343433464757213550",
  "right_serial": "0665FF535157808667132326",
  "connect_timeout_s": 5.0
}
```

起動ごとに番号が完全一致するSTMicroelectronicsのUSBシリアルポートを検索します。USBを抜き差しして `ttyACM0` 等の番号やUSBソケットが変わっても、左右・モーター定数・前進符号の対応は変わりません。接続直後の認識待ちは `connect_timeout_s` 秒（0〜30秒）です。`drive`・`check`・`inspect` で共通の検索処理を使います。未接続や番号の重複では開始せず、ポート使用中・アクセス権限のエラーも表示します。

従来の `left_port` / `right_port` も使用できます。固有番号とパスの両方を設定した場合は固有番号を優先し、対象が未接続でも古いパスへは接続しません。ポート指定で使う場合は `/dev/serial/by-id/…` を推奨します。**運転中のUSB切断は両輪停止・終了です。再接続後に同じ起動コマンドを実行し、中立・LB解放から操作を開始してください。** 固有番号の解決で使用中プロセスの排他ロックを解除することはありません。

R/Lは以前のESCによる実測値で、外部計測器での校正はしていません。R/Lを両方nullにするとESCに設定済みの値を使います。未設定なら始動を拒否し、自動同定は行いません。

| `drive` の設定 | 初期値 | 意味 |
| --- | ---: | --- |
| `max_current_a` | 2.0 | 各輪の速度制御で使うIq上限。0.1〜2.0 A |
| `min_speed_rpm` | 8.0 | 非ゼロ操作の最小速度 |
| `max_speed_rpm` | 25.0 | スティック最大時の車輪速度。設定上限25 RPM。実速度は電圧・負荷で制限 |
| `acceleration_rpm_s` | 20.0 | 目標速度の変化率。1〜20 RPM/s。大きいほど素早く加減速の目標を変更 |
| `steering_gain` | 1.5 | 旋回入力の倍率。0.5〜3.0 |
| `deadzone` | 0.12 | スティック中央の不感帯 |
| `input_timeout_s` | 0.5 | ゲームパッド入力・確認の監視時間 |
| `loop_timeout_s` | 0.15 | ホスト制御ループ遅延の許容時間 |
| `left_sign` / `right_sign` | 1 / -1 | 確認済みの前進方向 |

始動電流はESC内で `min(0.6 A, 電流上限)` に制限します。電流上限を2 Aにしても常時2 Aを流すわけではなく、速度を保つために必要な分を流します。`acceleration_rpm_s` は速度目標の変化率であり、減速時の実速度を保証する値ではありません。LB保持中の速度減少・中立・反転には制御減速を使います。LB解放・B・通信断はPWM停止です。旧電流指令版の `startup_current_a`、`startup_electrical_hz`、`slew_a_per_s` は削除しました。

実機用の `config.local.json` を設定例で上書きしないでください。新規設定時だけ `config.example.json` をコピーします。

```bash
# 現在のポート・USB固有番号・left/rightの対応を表示（回転指令なし）
uv run hg-cart devices --config config.local.json
uv run hg-cart demo --config config.local.json
# UARTログの受信のみ。停止を含めコマンドを送らない
uv run hg-cart inspect --config config.local.json --seconds 3
# 両輪を停止し、ゼロ点校正、通信仕様、電源、R/Lを確認。回転指令なし
uv run hg-cart check --config config.local.json
```

現在のF310はOS上で `Microsoft X-Box 360 pad`（USB `045e:028e`）として認識されます。このID、F310の `046d:c21d`、F710の `046d:c21f` に対応しています。`gamepad: null` で自動検出します。複数台接続時は使用する入力デバイスを指定してください。Dモードには対応していません。

`gamepad` は全ボタン、十字キー、スティック、トリガーを生値・正規化値で表示します。`受信イベント数` が操作で変化すれば信号を読めています。MODE等、OSへ独立したイベントが届かない本体スイッチは取得できません。

## 停止処理

- 起動時に両ESCのPWMを停止し、温度変化による電流センサーのずれを減らすためゼロ点を再校正します。通信仕様・電源・モーター定数を検証してから操作を受け付けます。
- 有線F310ではスティックを固定して操作できます。主ループが入力デバイスを確認し、USB読み取り失敗・古い入力キュー・キューあふれでは両輪停止後に終了します。USBデバイス確認は、同じ入力値のまま故障したコントローラの検出を保証するものではありません。
- F710は受信機だけ残る無線断を考慮し、入力イベントが0.5秒変化しなければ停止します。F710ではスティック固定でも停止します。
- 片輪のfault、目標速度の応答不一致・タイムアウト、状態ログ停止、ホスト制御ループ遅延では両輪を停止します。通信異常時に自動再接続・自動再始動はしません。
- `ping` は主制御ループだけから送信します。ホスト停止時にはESCの500 ms通信監視でPWMを停止します。独立watchdogも維持しています。
- 速度制御の連続運転は、明示的なUART `runrpm` だけで許可しています。他の既存ベンチ運転の10秒制限、始動タイムアウト、過電流・電圧・センサレス推定喪失・過速度等の保護は維持します。
- LB保持中の速度超過・減速時には最大0.6 Aの制動Iqを使います。過電圧保護は18〜22 Vのままです。坂道での停止保持は実装していません。

## ESCファームウェア

ユーザー指定の `/home/tako/STM32CubeIDE/workspace/B-G431B-ESC1` に変更を反映しています。これはそのプロジェクト独自のUART仕様で、MCSDKやSimpleFOCのコマンドではありません。

- [firmware/cart_direction.hpp](firmware/cart_direction.hpp)：逆転時の電流測定・PWM出力のV/W相交換、運転中の方向切替拒否、PWM停止後の2秒待機。制御減速完了時だけ次の始動を許可。
- [firmware/esc-bidirectional.patch](firmware/esc-bidirectional.patch)：従来の符号付き電流指令と方向制御への差分。
- [firmware/esc-speed.patch](firmware/esc-speed.patch)：その版からの速度制御対応差分。`cppmain.cpp` と `motor_control.hpp/.cpp` を変更します。
- [firmware/esc-response.patch](firmware/esc-response.patch)：速度制御版からの応答改善・2 A対応差分。始動短縮、始動中の目標更新、加速度設定、速度PI調整、UARTログ短縮を含みます。
- [firmware/esc-maneuver.patch](firmware/esc-maneuver.patch)：応答改善版からの制御減速・反転・25 RPM指令対応差分。

指定のプロジェクトには既に適用済みです。重ねてパッチを適用しないでください。既存の変更・サブモジュールは維持しています。

| UARTコマンド | 動作 |
| --- | --- |
| `cartcap` | `cart_protocol=4 signed_rpm=1 controlled_reverse=1 controlled_zero=1`、速度・電流範囲、監視時間を返す |
| `zero` | PWM停止中の電流ゼロ点校正。`calibration=started`、完了は `status` の `cal=ok` |
| `arm` → `runrpm 10 2 20` | 正方向10 RPM、Iq上限2 A、目標変化率20 RPM/sで始動 |
| `arm` → `runrpm -10 2 20` | 逆方向10 RPM、Iq上限2 A、目標変化率20 RPM/sで始動 |
| `rpm -8` | 逆方向の始動中・閉ループ運転中に目標を-8 RPMへ変更 |
| `rpm 0` | 制御減速後にPWM停止して `ready` へ。次の非ゼロ指令で再始動 |
| `stop` / Ctrl-C文字 | 即時PWM停止、保留指令を破棄 |
| `ping` | 500 ms監視を更新。速度指令の送信だけでは代用しない |
| `status` | 状態・fault・PWM・方向・要求/推定RPM・電流上限を返す |

始動時は8 RPMへ向けてセンサレス推定を確立し、その後に最新の目標速度へ移行します。Pythonは始動中も目標変更を送り、同じ方向の変更で始動手順をやり直しません。目標変更は最大50 Hzで送信し、未確認の指令は1件までに制限します。応答待ちの間に変わった古い目標をキューへ蓄積せず、次の送信では最新値を使います。運転中の周期ログを短縮し、指令応答のUART待ちを減らしています。`status` とfault発生時には詳細状態を返します。`runrpm` の加速度引数を省略した場合は20 RPM/sです。運転中の反対符号の `rpm` は、制御減速後にその方向へ再始動します。従来の `runiq` / `iq` は診断用に残していますが、Pythonの走行モードでは使いません。旧ファームウェアのままでは始動を拒否します。

RPM換算は既存プロジェクトの車輪1回転あたり199電気周期を使用します。表示値はセンサレス推定で、外部エンコーダの測定値ではありません。

現行ELFは `artifacts/firmware/hg-cart-maneuver-release.elf`、SHA-256・ビルド/書き込み記録は `artifacts/hardware/2026-10-14/maneuver/` にあります。リセット直後はPWM停止です。以前のELF・128 KiBバックアップも保持しています。

`tests/cart_response_test.cpp` の独立モデルでは、両方向・複数の初期回転子角・ADC量子化・加速度10/20 RPM/s・1 Aを超える負荷への追従・2 A指令上限・保護を確認し、AddressSanitizer/UndefinedBehaviorSanitizerでも通過しました。実機の電気機械特性すべてを再現するモデルではありません。Python 75テストと従来の速度制御モデルも通過しています。ホールを使った停止付近の制御や、逆転待機をなくす変更は含みません。

2026-10-14の制御減速・反転版（プロトコル4）では、車輪を浮かせて8→15→25→15 RPM、中立、後退、右旋回、左旋回、前進への復帰を確認しました。25 RPM指令で両輪の推定値は25.03 RPM前後、15↔25 RPMの変化は約0.52秒、直接反転して15 RPMへ到達するまで約2.3〜2.6秒でした。片輪だけを反転する区間では、他方は閉ループを維持しました。これは外部速度計ではなくESCの推定値による測定です。

最高速度設定は25 RPM、目標変化率20 RPM/s、旋回倍率1.5、Iq上限2 Aです。実機相電流ピークは1.543 A、バス電圧は19.339〜19.523 Vでした。通信断停止と最終PWM停止を両輪で確認しています。生ログは `artifacts/hardware/2026-10-14/maneuver/trial.json`、集計は `summary.json`、反転途中の停止確認は `reversal-cancel.json` です。90秒のF310操作確認では入力操作がなく、操作感のユーザー確認は未取得です。

`tests/cart_maneuver_test.cpp` で両方向・複数初期角・始動中の反転・ADC量子化・電流/電圧保護を検証しました。AddressSanitizer/UndefinedBehaviorSanitizer、従来の速度制御モデル、Python 77テスト、Release/Debugビルドが通過しました。LeakSanitizerは実行環境のptrace制約で無効にしています。

200 RPMは対応範囲にしていません。現在の換算（車輪1回転あたり199電気周期）と実測推定磁束約0.012 Wbから、200 RPMでは逆起電力振幅が約50 Vと計算され、約19 Vの電源では到達できません。25 RPMは無負荷での確認値で、接地時の速度・旋回力は未確認です。設定上限だけを200に変更しても解決しません。
